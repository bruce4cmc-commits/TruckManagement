# 卡車管理系統 V1.2－移除 Google Apps Script 改版影響清單

## 已確認需要修改的原附件

1. Google Apps Script + Supabase API 規格：**全面重寫**
2. System Flow：移除「Google Apps Script 設計」階段，改為 RLS/RPC
3. Wireframe：畫面基本不變，只修改技術依據與登入實作說明
4. 流程與管理方式：業務流程基本不變，修改技術範圍
5. Schema SQL：**必改**，原 V1.1 撤銷 authenticated 權限且無 RLS policy，無法支援前端直接 Data API
6. Seed SQL：密碼不再交給 Apps Script 設定
7. Verify SQL：增加 Auth 綁定及 RLS 驗證
8. Supabase 技術依據：改為 Publishable key + Auth + RLS
9. Google Sheets → Supabase 遷移說明：改為 GAS → Supabase Direct
10. 資料庫欄位規格：新增 `auth_user_id`，停止依賴 Apps Script Repository / password_hash

## 業務需求不變
- QR 七節點
- 120 分鐘 Cycle
- 140 分鐘 Cycle KPI
- 節點標準 +15 分鐘超時
- 楊梅出發 ±20 分鐘
- 漏掃不阻擋、不列異常
- 人工補正 / 更正保留原紀錄
- 週間計畫與兩車交錯
- 三端 Web App
- 不使用 GPS

## 必須特別注意
若要求「完全只有 Browser + REST/PostgREST，任何 Supabase Auth/RPC/Cron/Edge Function 都不用」，則下列既有需求無法在安全前提下完整保留：
- 安全的帳號密碼驗證
- 角色授權
- 管理員重設他人密碼
- 多表原子交易
- 定時超時判定
- 外部 Push 通知

因此 V1.2 採「無 Google Apps Script、無自建應用伺服器，但使用 Supabase 原生後端能力」。
