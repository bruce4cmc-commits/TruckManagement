# 卡車管理系統－System Flow V1.2（Supabase Direct）

## 1. 文件目的

本文件彙整目前已確認之卡車管理系統流程與操作邏輯，作為後續 Supabase 資料結構設計、Supabase REST/PostgREST、RLS/RPC 與 Web App 開發之依據。

本版聚焦：
- 週間車趟計畫
- 車輛交錯排程
- 司機登入與今日任務
- QR Code 節點回報
- 漏掃、重複掃描、離線補傳
- 超時與交通異常
- 即時車況
- 人工補正與已完成 Trip 更正
- 追加／取消 Trip
- 車輛／密碼／通知管理
- 主管 Dashboard 與 KPI 流程

**本版不包含 Supabase 資料表與欄位設計。**


本版系統基礎：
- 前端：HTML / CSS / JavaScript Web App
- 資料庫：Supabase PostgreSQL（REST/PostgREST）
- 司機端：手機 Web App
- 物流管理端：手機 / PC Web
- 主管端：PC / 平板 Dashboard
- 不使用 GPS

> 技術實作說明：移除 Google Apps Script 後，瀏覽器端使用 Supabase Publishable key 存取 Data API；登入與身分識別使用 Supabase Auth，資料授權由 PostgreSQL RLS 控制。複雜且需一致性之寫入邏輯可使用 PostgreSQL Function / RPC，定時工作使用 Supabase Cron。Secret key / service_role 不得放入瀏覽器。

# 2. 系統總流程

```text
物流管理人員
    │
    ▼
建立週間車趟計畫
    │
    ├─ 系統自動安排交錯車輛
    ├─ 可人工修改
    ├─ 檢查排程衝突
    └─ 儲存一週計畫
    │
    ▼
每日車趟計畫
    │
    ▼
司機登入
    │
    ▼
顯示今日任務
    │
    ▼
依計畫執行 Trip
    │
    ▼
各節點掃描 QR Code
    │
    ├─ 正常掃描
    ├─ 掃錯節點 → 警示但允許繼續
    ├─ 漏掃 → 不阻擋、不列異常
    └─ 無網路 → 暫存後補傳
    │
    ▼
系統更新即時車況
    │
    ├─ 正常
    ├─ 接近超時
    ├─ 超時
    └─ 交通／車輛異常
    │
    ▼
物流管理端即時監控
    │
    ▼
Trip完成
    │
    ▼
Cycle Time / KPI計算
    │
    ▼
物流主管 Dashboard
```

# 3. 週間計畫建立 Flow

```text
物流管理人員登入
        ↓
進入「週間車趟計畫」
        ↓
選擇週別
        ↓
建立方式
 ├─ 複製上週
 └─ 直接新增
        ↓
輸入每日Trip
        │
        ├─ 日期
        ├─ 楊梅計畫出發時間
        └─ 車輛
        ↓
系統自動產生Trip編號
        ↓
系統自動套用交錯排程
        ↓
物流人員確認
        │
        ├─ 接受
        └─ 手動修改
        ↓
系統執行排程衝突檢查
        │
        ├─ 無衝突 → 儲存
        └─ 有衝突 → 警告
                     │
                     ├─ 返回修改
                     └─ 強制儲存
        ↓
完成週間計畫
```

# 4. 車輛交錯排程 Flow

兩台車時：

```text
Day 1
#1 車01
#2 車02
#3 車01
#4 車02
...
```

若當日總趟數為奇數：

```text
Day 1 首車 = 車01
Day 1 車01多跑1趟
        ↓
Day 2 首車自動改為車02
```

系統原則：
- 自動套用交錯排程。
- 物流管理人員可人工變更。
- 若未來車輛數增加，排程邏輯須可擴充。

---

# 5. 排程衝突檢查 Flow

完整 Cycle 標準為 **120分鐘**。

例如：

```text
車01
09:00 出發
↓
標準下一次可出發
11:00
```

若物流人員設定：

```text
車01
10:00 再出發
```

系統：

```text
⚠ 排程衝突
上一趟尚未達標準Cycle完成時間

[返回修改]
[強制儲存]
```

物流管理人員可強制儲存。

# 6. 司機登入 Flow

```text
開啟固定網址
        ↓
選擇車號
        ↓
輸入密碼
        ↓
驗證
  ├─ 正確 → 登入
  └─ 錯誤 → 顯示錯誤
        ↓
```

補充規則：
- 原則上一車固定一司機。
- 臨時代班時允許司機自行選車。
- 物流管理人員可重設司機密碼。

# 8. 出發前提醒 Flow

建議預設：

> **計畫出發前10分鐘**

```text

        ↓
```

提醒分鐘數後續建議做成可調整參數。

# 9. QR掃描正常 Flow

例如目前預期：

> 新竹入廠

```text
司機按「掃描 QR Code」
        ↓
掃描新竹入廠QR
        ↓
系統辨識節點
        ↓
記錄掃描時間
        ↓
判定為正確節點
        ↓
更新Trip狀態
        ↓
顯示：
「回報成功」
「時間」
「下一節點」
        ↓
數秒後自動返回首頁
```

不需要二次確認。

---

# 10. 掃錯 QR Flow

例如系統預期：

> 新竹入廠

但司機掃：

> 新竹出廠

```text
掃描QR
   ↓
與預期節點不一致
   ↓
顯示警告
   │
   ├─ 返回重新掃描
   └─ 確認本次回報
             ↓
      接受本節點紀錄
             ↓
      更新流程
```

原則：

> **警示但不阻擋。**

---

# 11. 漏掃 Flow

例如：

```text
楊梅出廠   ✓
     ↓
新竹入廠   ← 漏掃
     ↓
新竹庫房   ✓
```

系統處理：

```text
偵測前節點未掃
        ↓
不阻擋目前掃描
        ↓
不列入異常Trip
        ↓
不進異常中心
        ↓
不發異常通知
        ↓
前節點維持未掃描
```

物流管理人員仍可選擇：

```text
[人工補正]
```

但不是強制。

---

# 12. 重複掃描 Flow

同一節點短時間重複掃描：

```text
第一次掃描
   ↓
有效
   ↓
第二次重複掃描
   ↓
忽略
```

若相同節點與前次相隔超過 **100分鐘**：

> 可判定為下一個 Cycle 的節點回報。

# 13. 離線掃描 Flow

```text

   ↓
偵測無網路
```

# 14. 標準 Cycle Flow

完整標準時間：

```text
楊梅出廠        09:00
↓ 30
新竹入廠        09:30
↓ 5
新竹車頭庫房    09:35
↓ 25
新竹出廠        10:00
↓ 30
楊梅入廠        10:30
↓ 5

↓ 10
楊梅裝車頭      10:45
↓ 15
下一趟楊梅出廠  11:00
```

完整 Cycle：

> **120分鐘**

# 15. 節點超時 Flow

每個節點：

> **標準時間 + 15分鐘 = 警示時間**

例如：

```text
楊梅→新竹
標準30分鐘
        ↓
45分鐘仍未掃新竹入廠
        ↓
產生超時異常
```

系統執行：

```text
超時成立
    ↓
車況改為紅色
    ↓
通知司機
    ↓
通知物流管理人員
    ↓
異常中心新增紀錄
```

# 18. 即時車況 Flow

本系統不使用 GPS。

即時車況依：

> **最後一筆有效 QR 紀錄**

判斷。

```text
楊梅出廠
→ 楊梅→新竹運輸中

新竹入廠
→ 新竹廠內移動中

新竹庫房
→ 卸車頭／裝引擎中

新竹出廠
→ 新竹→楊梅運輸中

楊梅入廠
→ 楊梅廠內移動中

楊梅卸引擎
→ 引擎卸貨／往車頭庫房

楊梅裝車頭
→ 待下一趟出發
```

# 24. 取消 Trip Flow

僅限未開始 Trip：

```text
選擇Trip
   ↓
[取消Trip]
   ↓
選擇原因
 ├─ 庫存調整（減少）
 ├─ 車輛異常
 └─ 其它
   ↓
確認
   ↓
狀態改為「已取消」
```

取消不等於刪除。

---

# 25. 已開始 Trip Flow

Trip 一旦開始：

不允許：
- 刪除
- 改成另一趟
- 更換車輛

允許：
- 異常註記
- 修訂後續尚未開始計畫

# 31. KPI 核心判定規則

## 31.1 楊梅出發準時

> **計畫出發時間 ±20分鐘**

## 31.2 Cycle 準時

> **Cycle Time ≤140分鐘**

## 31.3 節點超時

> **節點標準時間 +15分鐘**

## 31.4 異常 Trip

包含：
- 節點超時
- 塞車
- 事故
- 車故障
- 其它交通／運輸異常

不包含：
- 單純漏掃 QR
